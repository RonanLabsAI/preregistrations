# Bounded small-model calculator-agent pilot

Question: which eligible small model solves more frozen public tasks when given the same bounded arithmetic tool? Queue unit `bakeoff`, Qwen/Qwen3-4B and Qwen/Qwen3-8B, each within the approved 4B–14B class, same exact BF16 weights/revisions as costing. No retired models. Pinned vLLM, same GPU, cache OFF, eager, TP1, C1, context 8,192, seed 42, temperature zero, output cap 512 per turn and thinking disabled.

Public tasks: first 32 GSM8K test questions plus first 16 BBH multistep_arithmetic_two examples in repository order, frozen source revisions in sources.json and bytes in gsm8k-32.jsonl / bbh-16.jsonl. This is a tool-agent adaptation of public reasoning benchmarks, not the standard GSM8K/BBH evaluation recipe and not a software-engineering agent leaderboard. Scope is a prospective bounded calculator-agent pilot.

Agent has at most four model turns and three tool calls. Only calculator is executable: JSON tool and expression, parsed with a restricted AST allowing numeric constants, + - * /, parentheses and unary minus. No eval, shell, files, network or arbitrary model-generated code. Length, depth, magnitude and finite-value bounds apply. Tool results return as the next user observation; final answer is a JSON answer string. Malformed JSON, unsupported tools, tool errors or exhausted turns count incorrect, with traces retained. Score strict final-number equality against frozen public references; no model judge. No retries or task curation after seeing model output.

Primary: exact successes/48 per model with Wilson 95% intervals; publish GSM8K/BBH row IDs and traces for independent stratification. Secondary: tool-call frequency, failures, latency and tokens. Small convenience subsets limit generalization and cannot establish real-world autonomous-agent quality. Budget at most twelve GPU-hours including loading. Disjoint synthetic smoke input tests each model before admission; no smoke answers count toward the study.

Frozen prospectively on 2026-11-14 (PT), after PI work-selection approval. This version supersedes the held approval reservation for future work only. Historical receipts are not newly preregistered.

Authoritative identities: `freeze.json`, SHA-256 `4851a286f85c5766ef8e42bfd7dd39acd5727b33ae2e01be6b0e27aaa526a092`. It contains every model file digest, engine image/version, driver/platform fingerprint, workload/generator/scorer hashes, memory limits, seeds and costing constants. No weights are redistributed. Hardware: dedicated RTX PRO 6000 Blackwell Max-Q, BF16 for Qwen arms. Protected services are never changed; all inference uses named research routes.

Safety and interruption: only a renewable preemptible fleet claim permits GPU work. Check claim before every request and engine start. Admit only with at least 90,000 MiB free. Research yields to owner use. GapRunner owns launcher and container PID discovery; TERM checkpoints completed rows, stops only the owned engine, and retains prior evidence. Hard stop bounds remaining requests. Release bound is five minutes including claim expiry and stop allowance. Maximum lost work is one in-flight request/batch, bounded by three minutes; completed-row JSONL and checkpoint are durable. A resumed cache comparison is analyzed separately if the engine lost cache state. An interrupted needle/quality row is not scored; committed completed rows are retained. No silent retries of failed units. Prefix recovery replays complete engine strata into a new attempt rather than combining partially warmed caches.

Smoke is separate from scored data, uses a synthetic disjoint control, tests actual startup/request counters/stop/checkpoint and records measured release evidence. Engine-start failures, counter failures, interruptions, budget exhaustion and unrun dispositions are outcomes, never fabricated nulls. Kill on missing claim, production demand, insufficient memory, frozen-input/model drift, OOM, missing counters, scoring failure, failed cleanup or budget exhaustion. Publicly record every outcome, null or not. Posts/papers require a meaningful null and PI tier decision; this preregistration authorizes no post, paper, email or submission.

All answers, token counters, request wall times, model/engine identities, attempts and failure dispositions go to immutable receipts in a K3 package. Raw UTC machine timestamps may remain inside receipts; human reports use PT. Every reported estimate includes its denominator or uncertainty interval. Smoke measurements are never pooled with scored observations. Correctness uses exact normalized outputs, including failures and empty answers as incorrect when transport and counters are valid. Harness/transport errors are labeled invalid, not model errors. No benchmark-general superiority claim is made from these small fixed subsets.

Execution: `python runner.py --product cheap-model-bakeoff --arm bakeoff` under the queue-provided environment, with `--smoke` for disjoint smoke controls. Runtime files supply private serving and claim details and are excluded from the public record. Inputs and runner below are frozen by digest; changes require an append-only dated amendment before additional measurements.
