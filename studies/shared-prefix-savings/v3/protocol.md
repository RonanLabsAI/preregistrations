# Matched shared-prefix savings across serving engines

Question: how much warm-request wall time does prefix reuse save within each pinned engine, and do the matched engine results differ? Public sources describe the mechanisms: https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/ and https://docs.sglang.ai/advanced_features/server_arguments.html . This tests the pinned implementations, not every release.

Arms `vllm` and `sglang`, same Qwen/Qwen3-4B revision and exact BF16 weight/tokenizer digests, same dedicated GPU, TP1, BF16 KV, eager execution, maximum four running requests, context 8,192, prefill cap 8,192, seed 42. Both caches have capacity 32,768 tokens, 16-token blocks/pages; vLLM KV bytes are 4,831,838,208 (36 layers, eight KV heads, head dimension 128, K+V, two bytes). SGLang max-total-tokens is 32,768. Both have ample memory margin; startup logs must verify effective capacities before treating a difference as fair.

Each engine starts fresh for cache OFF then ON; no other engine runs concurrently. Same fixed two short warmup requests. Workload: 128 copies of the public sentence in runner.py about colored shapes, prefixed with a unique repetition identifier. Four simultaneous questions with the same prefix and distinct suffixes, output cap 16, temperature zero. Five repetitions per cache mode, each with one first-use cold batch then one identical warm batch. Shapes, bytes, warmup and cache capacities are identical between engines. No off-engine cache flush is assumed; new repetition prefixes isolate prior prefix reuse. Cache OFF is a fresh process, not an API toggle. Full request text and batch construction are code-frozen. Engine order is fixed, a limitation; measure on the same idle GPU without concurrent work and retain order in receipts.

Primary: wall time per four-request warm batch, cache ON/OFF ratio within engine. Five batches per mode, 2,000-resample percentile bootstrap 95% intervals with seed 42. Report cold batches separately. Secondary: individual response latency, usage counters and output correctness (blue). These are end-to-end wall times, not isolated prefill kernel timings or TTFT. Engine-specific optimizations remain part of the engine effect; mismatched effective KV capacity invalidates the cross-engine comparison. Never call unequal capacities fair. Budget at most twelve GPU-hours, two queue units; smoke uses one repetition, kept separate.
