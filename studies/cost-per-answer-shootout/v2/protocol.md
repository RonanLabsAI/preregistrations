# Modeled dollars per correct public math answer

Question: which of two local eligible models gives lower modeled GPU cost per correct answer under matched cache controls? Arms within queue unit `cost`: Qwen/Qwen3-4B and Qwen/Qwen3-8B, exact revisions/files in freeze.json, BF16, pinned vLLM, cache OFF and ON as fresh processes. Same dedicated GPU, context 8,192, TP1, eager mode, C1, temperature zero, seed 42, output cap 512, thinking disabled through chat template. Same two synthetic warmup requests, excluded from scoring.

Public benchmark: first 32 test rows of openai/grade-school-math at the frozen Git revision in sources.json, copied byte-identifiably to gsm8k-32.jsonl with row IDs. Four conditions, 32 attempts each; frozen order model 4B then 8B, cache OFF then ON. Identical system prompt across rows makes shared system-prefix reuse the treatment. No prompt/result cache outside the serving engine; router retries zero. Exact numeric normalization removes thousands commas and a dollar sign but refuses explanatory text; expected value is the final number after the benchmark's answer delimiter. This deliberately measures strict final-answer compliance, not chain-of-thought grading.

GPU energy is explicitly an estimate: trapezoid of board power sampled immediately before and after the full request, times elapsed seconds. It excludes CPU, PSU, cooling and engine load. Never label it wall-plug energy or a meter measurement. Hardware amortization is an assumption, not an invoice: USD 10,000 GPU capital, three-year straight line, zero residual, 50% useful utilization; electricity USD 0.20/kWh. Formula per attempt: elapsed_seconds * capital/(years*365.25*86400*utilization) + estimated_joules/3600000 * electricity_rate. Include incorrect/valid attempts in cost numerator and correct answers in denominator. No correct answers => undefined/infinite cost, never zero. Report energy and amortized hardware separately; loading occupancy is reported as GPU-hours, excluded from steady-state modeled answer cost. Sensitivity: users can recompute hardware contribution inversely with utilization and linearly with capital; these constants are not universal acquisition facts.

Primary: total modeled USD / correct answers, with denominator and 2,000-row-resample percentile bootstrap 95% interval per condition (seed 42; zero-correct resamples have infinite cost). Also report exact successes/32 with Wilson 95% intervals, latency and token counters. Cost is workload-specific. Budget at most twelve GPU-hours including loading. Disjoint synthetic smoke math question is excluded.

Frozen prospectively on 2026-11-14 (PT), after PI work-selection approval. This version supersedes the held approval reservation for future work only. Historical receipts are not newly preregistered.

Authoritative identities: `freeze.json`, SHA-256 `18b10ae34b87ae16379e3ec2e9f009c5d3a210177dd255aab4e81ca788156a45`. It contains every model file digest, engine image/version, driver/platform fingerprint, workload/generator/scorer hashes, memory limits, seeds and costing constants. No weights are redistributed. Hardware: dedicated RTX PRO 6000 Blackwell Max-Q, BF16 for Qwen arms. Protected services are never changed; all inference uses named research routes.

Safety and interruption: only a renewable preemptible fleet claim permits GPU work. Check claim before every request and engine start. Admit only with at least 90,000 MiB free. Research yields to owner use. GapRunner owns launcher and container PID discovery; TERM checkpoints completed rows, stops only the owned engine, and retains prior evidence. Hard stop bounds remaining requests. Release bound is five minutes including claim expiry and stop allowance. Maximum lost work is one in-flight request/batch, bounded by three minutes; completed-row JSONL and checkpoint are durable. A resumed cache comparison is analyzed separately if the engine lost cache state. An interrupted needle/quality row is not scored; committed completed rows are retained. No silent retries of failed units. Prefix recovery replays complete engine strata into a new attempt rather than combining partially warmed caches.

Smoke is separate from scored data, uses a synthetic disjoint control, tests actual startup/request counters/stop/checkpoint and records measured release evidence. Engine-start failures, counter failures, interruptions, budget exhaustion and unrun dispositions are outcomes, never fabricated nulls. Kill on missing claim, production demand, insufficient memory, frozen-input/model drift, OOM, missing counters, scoring failure, failed cleanup or budget exhaustion. Publicly record every outcome, null or not. Posts/papers require a meaningful null and PI tier decision; this preregistration authorizes no post, paper, email or submission.

All answers, token counters, request wall times, model/engine identities, attempts and failure dispositions go to immutable receipts in a K3 package. Raw UTC machine timestamps may remain inside receipts; human reports use PT. Every reported estimate includes its denominator or uncertainty interval. Smoke measurements are never pooled with scored observations. Correctness uses exact normalized outputs, including failures and empty answers as incorrect when transport and counters are valid. Harness/transport errors are labeled invalid, not model errors. No benchmark-general superiority claim is made from these small fixed subsets.

Execution: `python runner.py --product cost-per-answer-shootout --arm cost` under the queue-provided environment, with `--smoke` for disjoint smoke controls. Runtime files supply private serving and claim details and are excluded from the public record. Inputs and runner below are frozen by digest; changes require an append-only dated amendment before additional measurements.
